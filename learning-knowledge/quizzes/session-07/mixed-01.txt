SESSION: 7
TITLE: Git, GitHub, ветки, commits и память проекта

================================================================
BLOCK 1 - Git: зачем он нужен
================================================================

[QCM]
Q1. Что такое Git в самой простой формулировке?

    A) Сайт, где публикуют приложения
    B) Система, которая хранит историю изменений проекта
    C) Язык программирования
    D) Хостинг вроде Vercel

ANSWER: B
EXPLANATION: Git помогает проекту помнить, что менялось, когда менялось и в каком состоянии был проект.

---

[VF]
Q2. Git нужен только профессиональным разработчикам. Для маленького учебного проекта он бесполезен.

ANSWER: false
EXPLANATION: Даже в маленьком проекте Git помогает видеть изменения, возвращаться назад и не плодить папки `final-v2`.

---

[QCM]
Q3. Почему Git лучше, чем папки `final`, `final-v2`, `final-v2-real`?

    A) Git автоматически делает сайт красивее
    B) Git хранит нормальную историю версий внутри одного проекта
    C) Git удаляет все ошибки
    D) Git заменяет Next.js

ANSWER: B
EXPLANATION: Копии папок имитируют память. Git дает проекту настоящую структурированную память.

---

[OPEN]
Q4. Объясните своими словами: какую проблему Git решает в проекте?

ANSWER: Git хранит историю проекта; показывает что изменилось; помогает вернуться к старому состоянию; убирает хаос копий папок; помогает работать аккуратнее
EXPLANATION: Ответ не должен быть технически идеальным. Главное понять: Git дает проекту память.

---

[VF]
Q5. Git можно использовать на своем компьютере даже без GitHub.

ANSWER: true
EXPLANATION: Git может работать локально. GitHub нужен, чтобы хранить и делиться этой историей онлайн.

---

================================================================
BLOCK 2 - Commit: сохранить состояние проекта
================================================================

[QCM]
Q6. Что такое commit?

    A) Техническая фотография состояния проекта с сообщением
    B) Кнопка, которая сразу выкладывает сайт в интернет
    C) Полная ручная копия проекта в новую папку
    D) Команда для запуска `localhost`

ANSWER: A
EXPLANATION: Commit сохраняет состояние проекта в истории Git и добавляет сообщение, чтобы было понятно, что изменилось.

---

[VF]
Q7. Если вы сохранили файл в VS Code, Git автоматически создал commit.

ANSWER: false
EXPLANATION: Сохранить файл и сделать commit - это разные действия. Commit нужно создать отдельно.

---

[QCM]
Q8. Какая последовательность лучше всего описывает создание commit?

    A) `git commit` -> `git add` -> изменить файл
    B) изменить файл -> `git add` -> `git commit`
    C) `git push` -> изменить файл -> `git commit`
    D) `npm run dev` -> `git commit` -> `localhost`

ANSWER: B
EXPLANATION: Сначала вы меняете файл, подготавливаете изменения и сохраняете их в историю.

---

[OPEN]
Q9. Зачем commit нужно сообщение?

ANSWER: Сообщение объясняет что изменилось; помогает позже понять историю проекта; помогает найти нужный момент; показывает смысл изменения
EXPLANATION: Хорошее сообщение commit помогает будущему вам, другим людям и иногда ИИ понять историю проекта.

---

[QCM]
Q10. Вы изменили страницу и сделали commit, но не сделали push. Где сейчас находится это изменение?

    A) В локальной истории Git на вашем компьютере
    B) Автоматически на GitHub
    C) Автоматически в production на Vercel
    D) Только в браузере

ANSWER: A
EXPLANATION: Commit остается локальным, пока вы не отправили его наружу через `push`.

---

[VF]
Q11. Commit автоматически отправляет изменения на GitHub.

ANSWER: false
EXPLANATION: Commit и push - разные действия. Commit сохраняет локально, push отправляет на GitHub.

---

[QCM]
Q12. Какая команда обычно отправляет локальные commits на GitHub?

    A) `git push`
    B) `npm run dev`
    C) `git status`
    D) `localhost`

ANSWER: A
EXPLANATION: `git push` отправляет локальную историю Git в удаленный репозиторий, например на GitHub.


---

================================================================
BLOCK 3 - Ветка: работать, не ломая главную версию
================================================================

[QCM]
Q13. Что такое ветка (branch) в Git?

    A) Отдельная линия работы внутри того же проекта
    B) Новый аккаунт GitHub
    C) Ручная копия папки проекта на рабочем столе
    D) Файл с инструкциями для ИИ

ANSWER: A
EXPLANATION: Ветка позволяет работать над идеей, исправлением или функцией отдельно от основной линии проекта.

---

[VF]
Q14. Ветка Git - это то же самое, что папка `project-v2`.

ANSWER: false
EXPLANATION: Ветка не является хаотичной копией папки. Это управляемая Git линия работы в том же проекте.

---

[QCM]
Q15. Зачем создавать ветку перед новой функцией или экспериментом?

    A) Чтобы пробовать изменения, не ломая сразу главную версию
    B) Чтобы удалить историю проекта
    C) Чтобы сайт быстрее публиковался
    D) Чтобы не писать сообщение commit

ANSWER: A
EXPLANATION: Ветка изолирует работу. Если идея работает, ее можно потом вернуть в главную линию проекта.

---

[VF]
Q16. Если я изменил файл в одной ветке, ветка `main` автоматически изменилась в тот же момент.

ANSWER: false
EXPLANATION: Изменения остаются в той ветке, где вы их сделали, пока вы сами не перенесете их в другую ветку.

---

[OPEN]
Q17. Объясните ветку простой аналогией.

ANSWER: Ветка похожа на параллельный путь проекта; можно попробовать идею отдельно от главной дороги; если идея работает, ее можно вернуть в главную версию
EXPLANATION: Главное понять изоляцию: ветка позволяет экспериментировать, не ломая основную версию.

---

[QCM]
Q18. Что во многих проектах часто означает ветка `main`?

    A) Основная или стабильная версия проекта
    B) Ветка только для картинок
    C) Папка `node_modules`
    D) Админский аккаунт GitHub

ANSWER: A
EXPLANATION: Часто `main` - это главная линия проекта. Но связь с production зависит от настроек конкретного проекта.

---

[VF]
Q19. В одном Git-проекте может быть несколько веток.

ANSWER: true
EXPLANATION: Это одна из важных возможностей Git: несколько линий работы могут существовать в одном проекте.

---

[QCM]
Q20. Что обычно делают, когда работа в отдельной ветке закончена и проверена?

    A) Интегрируют ее в главную ветку
    B) Удаляют GitHub
    C) Начинают весь проект заново в новой папке
    D) Меняют язык проекта

ANSWER: A
EXPLANATION: Частая логика такая: сделать работу в отдельной ветке, проверить ее, затем вернуть в основную версию.

---

================================================================
BLOCK 4 - Git, GitHub, push и восстановление проекта
================================================================

[QCM]
Q21. В чем лучшая разница между Git и GitHub?

    A) Git - система истории, GitHub - онлайн-платформа для хранения Git-репозиториев
    B) GitHub - язык программирования, Git - сайт
    C) Git нужен для дизайна, GitHub нужен для JavaScript
    D) Разницы нет

ANSWER: A
EXPLANATION: Git - это инструмент контроля версий. GitHub - сервис в интернете, который работает с Git-репозиториями.

---

[VF]
Q22. Если я изменил файл на своем компьютере, GitHub автоматически получил это изменение без моих действий.

ANSWER: false
EXPLANATION: GitHub не видит локальные изменения сам. Нужно сделать commit и push, чтобы отправить историю на GitHub.

---

[OPEN]
Q23. Что нужно сделать, чтобы GitHub мог помочь восстановить проект после удаления локальной папки?

ANSWER: Нужно сохранить изменения в Git через commit и отправить их на GitHub через push; на GitHub должна быть актуальная версия репозитория
EXPLANATION: GitHub может восстановить только то, что уже было отправлено в удаленный репозиторий.


---

[VF]
Q24. Если мой проект был отправлен на GitHub, а потом я удалил папку проекта на компьютере, я могу восстановить проект с GitHub.

ANSWER: true
EXPLANATION: Если проект и его история были отправлены на GitHub, их можно восстановить, например через клонирование.

---

[QCM]
Q25. Вы изменили файлы на компьютере, но не сделали ни commit, ни push. Потом удалили папку. Может ли GitHub восстановить эти последние изменения?

    A) Да, потому что GitHub автоматически читает компьютер
    B) Да, потому что VS Code всегда отправляет файлы онлайн
    C) Нет, GitHub может восстановить только то, что было отправлено на GitHub
    D) Да, если браузер был открыт

ANSWER: C
EXPLANATION: GitHub не может восстановить изменения, которые никогда не были ему отправлены.

---

[OPEN]
Q26. Друг говорит: "GitHub - это автоматическая резервная копия всего моего компьютера." Исправьте эту фразу.

ANSWER: GitHub может хранить копию репозитория; на GitHub есть только то, что было сохранено через commit и отправлено через push; локальные изменения без push не сохраняются на GitHub; GitHub не сохраняет весь компьютер
EXPLANATION: GitHub очень полезен, но он не является автоматической резервной копией всего компьютера.

---

================================================================
BLOCK 5 - Vercel и файлы инструкций для ИИ
================================================================

[QCM]
Q27. Какую роль выполняет Vercel в цепочке деплоя?

    A) Хранит только сообщения commit
    B) Берет версию проекта, публикует приложение онлайн
    C) Полностью заменяет GitHub
    D) Сам пишет код проекта

ANSWER: B
EXPLANATION: GitHub хранит код и историю онлайн. Vercel строит и публикует версию проекта.

---

[VF]
Q28. Vercel автоматически видит любые локальные изменения на компьютере, даже если они не были отправлены на GitHub.

ANSWER: false
EXPLANATION: Vercel работает с версией проекта, которая доступна через GitHub или другой подключенный Git-провайдер, а не с несохраненными локальными файлами.

---

[QCM]
Q29. Зачем проекту нужен файл инструкций для ИИ, например `AGENTS.md`, `CLAUDE.md` или `GEMINI.md`?

    A) Чтобы полностью заменить Git
    B) Чтобы дать ИИ устойчивый контекст и правила работы в проекте
    C) Чтобы автоматически сделать push
    D) Чтобы Vercel не требовал GitHub

ANSWER: B
EXPLANATION: Файл инструкций помогает ИИ лучше понимать проект, но не заменяет точный запрос и проверку результата.


---

[OPEN]
Q30. Дайте простую цепочку от локального изменения до обновленного сайта через GitHub и Vercel.

ANSWER: Я меняю проект локально; делаю commit; делаю push на GitHub; Vercel видит новую версию; Vercel публикует или обновляет URL
EXPLANATION: Сайт появляется онлайн через цепочку действий. Это не происходит магически после любого локального изменения.
